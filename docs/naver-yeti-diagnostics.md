# 네이버 Yeti 접속 진단 (Cloudtype)

이 문서는 **실제 검색로봇 방문과 모의 접속 검사**를 구분하기 위한 절차입니다.

1. Cloudtype 관리화면에서 스마트24 운영 서비스를 열고 **실행 로그**를 확인합니다.
2. `SEO_YETI_UA `라는 접두어가 붙은 로그 줄을 찾습니다.
3. 각 줄에는 UTC 시각(`at`), 요청 경로(`path`), 실제 애플리케이션 HTTP 결과(`status`)만 기록합니다. IP, 쿠키, 검색어, 유입경로, 요청 헤더 본문은 기록하지 않습니다.
4. `200`: 해당 요청이 애플리케이션에서 정상 처리되었습니다. **색인이나 실제 네이버 로봇임을 증명하지는 않습니다.**
5. `403`, `404`, `429`, `5xx`: 해당 경로와 서버/보안 정책을 점검할 단서입니다.
6. **로그가 없다면** 아직 로봇 방문이 없었거나, CDN/호스팅 계층에서 먼저 거부되었거나, 로그 보관 기간이 지났을 수 있습니다. 이것만으로 네이버가 차단되었다고 단정할 수 없습니다.

중요: User-Agent 문자열 `Yeti`는 누구나 흉내 낼 수 있습니다. 방문 주체를 확정하려면 Cloudtype/프록시의 **원본 접속 IP**를 관리자 권한으로 확인하고, 네이버 공식 [역방향 DNS 및 정방향 일치 확인](https://searchadvisor.naver.com/guide/seo-basic-firewall)을 수행해야 합니다.

GitHub Actions의 모의 Yeti 점검은 `X-Smart24-Monitor: github-health-probe` 헤더를 보내므로 위 로그에서 제외됩니다. 미래의 실제 요청만 기록됩니다. 2026년 10월 29일 이전 접속 기록은 이 변경으로 복원되지 않습니다.

Cloudtype의 공식 안내: https://docs.cloudtype.dev/ko/developers/log
